# Работа с жалобами

В приложении на каждой странице доступна кнопка **Report a problem**. Жалобы
хранятся на сервере в той же SQLite-базе, что и раздачи. Каждая жалоба получает
числовой ID; первый ID — `1000`, затем `1001`, `1002` и так далее.

## Как тестеру отправить жалобу

1. Не покидая экрана, на котором проявилась проблема, нажать **Report a problem**.
2. В поле **Description** кратко написать, что выглядит неправильно и какой
   результат ожидался.
3. Нажать **OK**. Кнопка **Cancel** закрывает окно без отправки.
4. Передать разработчику показанный номер, например `1000`.

Сервер автоматически сохраняет состояние раздачи на момент отправки:

- расклад и полный борд;
- игроков, их стеки, позиции и карты;
- банк, ставки, блайнды и внесённые суммы;
- последовательность действий;
- текущую улицу и активного игрока;
- seed и код раздачи;
- рассчитанный результат, если раздача завершена;
- commit и время сборки сервера;
- тип страницы, размер окна и User-Agent.

Токены игроков не сохраняются. URL страницы целиком также не отправляется,
поскольку ссылка игрока содержит токен доступа.

## Как получить жалобу по ID

```http
GET /api/problems/1000
```

Ответ — JSON с описанием, контекстом и snapshot раздачи:

```json
{
  "id": 1000,
  "created": 1785357138000,
  "description": "После raise неверно уменьшился стек",
  "build": {
    "commit": "abc123",
    "buildTimeGmt": "2026-07-29 14:30:00 GMT"
  },
  "context": {
    "page": "player",
    "handId": "..."
  },
  "hand": {
    "players": [],
    "actions": []
  }
}
```

Если на сервере задана переменная `PROBLEM_API_TOKEN`, для чтения нужен
read-only токен:

```http
Authorization: Bearer <PROBLEM_API_TOKEN>
```

Создание жалобы из интерфейса не требует этого токена. Это позволяет тестерам
отправлять отчёты, но не читать чужие раздачи.

## Как разбирать жалобу здесь

Для локального или доступного из рабочей среды сервера достаточно написать:

> Разбери жалобу 1000

Адрес API должен быть известен в рабочей среде. Рекомендуемые переменные:

```text
PROBLEM_API_URL=https://example.test/api/problems
PROBLEM_API_TOKEN=read-only-secret
```

Токен нельзя добавлять в Git или отправлять в чат. После получения JSON раздачу
можно воспроизвести по `hand.dealSeed` и `hand.actions`, а состояния расчёта
сравнить со snapshot из жалобы.

## API создания жалобы

Интерфейс отправляет:

```http
POST /api/problems
Content-Type: application/json
```

```json
{
  "description": "После call неверно посчитался банк",
  "page": "player",
  "handId": "...",
  "playerId": "P1",
  "viewport": {
    "width": 1440,
    "height": 900
  }
}
```

Успешный ответ:

```json
{
  "id": 1000,
  "created": 1785357138000
}
```

Описание обязательно и ограничено 2000 символами. Если передан неизвестный
`handId`, сервер вернёт `404` и жалоба не будет создана.

## Резервная копия по электронной почте

Чтобы жалобы не исчезали вместе с эфемерной SQLite-базой, сервер может после
сохранения отправлять полную JSON-копию жалобы через Gmail SMTP. В копию входят
контекст, snapshot раздачи, seed и действия, необходимые для воспроизведения;
токены доступа игроков туда не попадают.

```text
PROBLEM_EMAIL_TO=pulsarik@gmail.com
GMAIL_USER=pulsarik@gmail.com
GMAIL_APP_PASSWORD=xxxx xxxx xxxx xxxx
```

`GMAIL_APP_PASSWORD` — это отдельный пароль приложения Google, а не пароль от
аккаунта. Он задаётся только как secret в окружении Render и не добавляется в
Git. Если почтовая доставка временно не работает, жалоба всё равно сохраняется
в SQLite, а ошибка отправки записывается в лог сервера.
