# ИИ-комментатор: настройка первого выпуска

Реализована генерация новых комментариев через Groq и синтез через Google Cloud Text-to-Speech. Аудиозаготовок и браузерного синтеза речи нет. При выключенной функции игра работает как прежде.

## Включение

Настройки задаются в окружении **серверного процесса** (например, в настройках хостинга). Приложение само не загружает `.env`. Не помещать ключи или JSON учётной записи в репозиторий и переменные `VITE_*`.

| Переменная | Значение / назначение |
| --- | --- |
| `COMMENTARY_ENABLED` | `true` включает функцию; без этого флага внешних вызовов нет. |
| `GROQ_API_KEY` | Ключ Groq. Без него функция недоступна. |
| `COMMENTARY_TEXT_MODEL` | По умолчанию `qwen/qwen3.8-27b`. Запрос использует `reasoning_effort: none` и JSON mode; другая модель должна поддерживать эти параметры. |
| `COMMENTARY_GOOGLE_TTS` | `true` включает голос. Без этого доступен только режим субтитров. |
| `GOOGLE_CLOUD_PROJECT` | Проект Google Cloud с включёнными биллингом и Cloud Text-to-Speech API; используется как quota project. |
| `GOOGLE_APPLICATION_CREDENTIALS` | При использовании файла service account — абсолютный путь к JSON **вне репозитория**. Можно вместо файла использовать штатные Application Default Credentials окружения. |
| `COMMENTARY_VOICE_RU` | По умолчанию `ru-RU-Chirp3-HD-Charon`. |
| `COMMENTARY_VOICE_EN` | По умолчанию `en-US-Chirp3-HD-Charon`. |
| `COMMENTARY_DAILY_TOKENS` | Консервативный дневной лимит приложения для текста, по умолчанию `180000`. |
| `COMMENTARY_MONTHLY_CHARACTERS` | Месячный лимит приложения для синтеза, по умолчанию `900000`. |
| `COMMENTARY_COOLDOWN_SECONDS` | Минимальная пауза между попытками за столом, по умолчанию `12` секунд (максимум `3600`). |
| `COMMENTARY_HAND_GAP` | Минимальная разница номеров комментируемых раздач, по умолчанию `1`: подходящие события могут звучать в соседних раздачах. |
| `COMMENTARY_HOURLY_ATTEMPTS` | Максимум попыток на стол в календарный час UTC, по умолчанию `60`. |

Google использует OAuth через `google-auth-library` и ADC. Для локальной разработки можно выполнить `gcloud auth application-default login` и настроить quota project; для хостинга предпочтительны привязанная service account / workload identity. Учётная запись должна иметь необходимые права вызова API и использования quota project. Google API key в эту реализацию не входит. [Аутентификация Google Cloud TTS](https://docs.cloud.google.com/text-to-speech/docs/authentication).

После изменения окружения перезапустить сервер. Справа в шапке стола находится иконка звука: нажатие включает или выключает комментатора. Для нового пользователя голос и субтитры включены; ранее сохранённый выбор сохраняется. Язык и громкость находятся во вкладке «Настройки» / “Settings” (на мобильном столе — через меню). Все предпочтения сохраняются локально. Если браузер блокирует озвучку, та же иконка предлагает «Включить звук»: нажатие запускает текущую реплику. Субтитры видны под шапкой только во время комментария.

Голос `Charon` — техническое начальное значение. Перед публичным включением прослушать его на русских покерных репликах и сравнить с `ru-RU-Chirp3-HD-Orus`; качество и реальные задержки пока не проверены.

## Поведение

- Работает после **нового сохранённого хода** человека, бота либо таймера: во время торговли и после завершения раздачи. Подключение к существующей раздаче не запускает генерацию.
- Во время торговли поводом служат олл-ин, повышение после повышения, крупная ставка/повышение или заметное публичное изменение доски: пара, три карты одной масти, связанные ранги либо возможность квалифицирующего лоу. Комментатор описывает только текстуру общей доски и не приписывает игроку готовую комбинацию. Крупным считается увеличение текущей ставки минимум на 6 больших блайндов и минимум на половину банка перед ходом; размер выбранной кнопки сам по себе не повод. Обычные чеки, коллы и фолды молчат. Если ход перевёл игру на следующую улицу, вместо запоздалой реплики о ходе может прозвучать комментарий о новой доске; при завершении раздачи рассматривается итог.
- Поводы: победа в партии, выигрыш хай и лоу всех оспариваемых банков, вылет, крупный оспариваемый банк, новый единоличный лидер по фишкам, обычная победа без вскрытия, получение доли хай или лоу. Возврат своей ставки не считается отдельной победой. Досрочное завершение и повторы раздач не комментируются.
- За раздачу допускается не более двух попыток во время игры и одной после результата. По умолчанию между любыми соседними попытками за столом проходит минимум 12 секунд; подходящие события могут комментироваться и в соседних раздачах. Максимум — 60 попыток на стол в час. Это предел частоты, а не гарантия: отсутствие интересного события, слушателя, бюджет или ответ модели могут сделать паузу длиннее. Пауза, интервал раздач и почасовой предел задаются переменными выше. Дневной бюджет текста и месячный бюджет голоса сохранены.
- На стол выбирается до трёх фактов, сначала значимые результаты. Одна генерация на язык для всех подписчиков; TTS вызывается только при наличии слушателя голоса на этом языке.
- Модель получает разрешённые факты с метками игроков, до трёх последних реплик и краткий публичный контекст завершённой раздачи: без вскрытия / шоудаун, размер оспариваемого банка (малый — менее 6 больших блайндов, средний — от 6 до 20, крупный — от 20), наличие олл-ина среди участников вскрытия или оставшегося игрока, побочных банков и выплаты лоу. Неоспариваемый банк не оценивается как крупный; отсутствие вскрытия не означает отсутствие возможной лоу-комбинации.
- Во время торговли модель получает текущую улицу, число оставшихся участников и факт значимого действия. Для торговли и итога добавляются счётчики ставок, повышений, коллов и фолдов, а также **последние пять публичных ходов по порядку**: метка игрока, улица, действие и категория общей ставки на этой улице (малая — менее 6 больших блайндов, средняя — от 6 до 20, крупная — от 20). Категория не описывает величину отдельного повышения. Эта последовательность позволяет назвать игроков в реальной цепочке действий; причину хода или силу руки из неё не выводят.
- Подача чередуется: азартный спортивный комментарий, сухая покерная ирония, игровая метафора. Во время торговли — одно короткое предложение о действии без предсказания ответа или победителя. После завершения — результат с уместной связью с торговлей, затем при желании короткая шутка о ситуации. При вылете или завершении партии — уважительный тон без шуток над проигравшим. Модель должна менять начала фраз и образы, а не повторять один слоган.
- Карты, полный борд, комбинации, внутренние оценки ботов, токены и имена игроков модели не отправляются. Очищенные имена подставляются после проверки текста. Истории серий побед, «камбэков», намерений и эмоций в контексте нет — придумывать их запрещено.
- Проверки текста отбрасывают неверные идентификаторы фактов и метки, числа, некоторые запрещённые утверждения и точные повторы. Это не доказательство семантической правильности свободного текста модели; оценочные игровые сессии обязательны.
- Таймаут текста до 5 секунд, речи до 6 секунд, срок для начала воспроизведения 12 секунд с момента события. Поздние ответы пропускаются. Уже начатое аудио может закончить фразу после этого срока (защитный предел — ещё 15 секунд).
- Субтитры и голос ждут соответствующей версии игры. Реплика о торговле действует только на своей улице: переход к следующей улице или результату отменяет её, в том числе уже начатое аудио. Сервер проверяет актуальность перед генерацией, после текста и перед публикацией; запоздавшая реплика пропускается с причиной `stale_action`. Кнопку следующей раздачи можно нажать во время итоговой фразы: запрос отправляется сразу, а переход на новую раздачу происходит после окончания озвучки. Смена раздачи другим способом, языка, режима, отключение соединения, уход со страницы или скрытие вкладки также отменяют старую реплику.
- Подключённый голосовой чат передаёт активность говорящих: комментатор ждёт тишины, а начатая речь прерывается при разговоре человека. Разговоры не записываются и не отправляются в модели.
- Web Locks координируют озвучку нескольких вкладок, если API доступен в браузере. Явный повтор после запрета autoplay запускается непосредственно пользовательским нажатием.
- При отказе TTS остаются субтитры. Повторяющиеся ошибки каждого провайдера включают паузу обращений на минуту. Автоматических повторов неоднозначных платных запросов нет.

## Лимиты и хранение

SQLite хранит уникальные события, опубликованные реплики с метками вместо имён и счётчики. Повтор команды, reconnect и перезапуск не создают повторную генерацию одного события. Невыполненные задания после рестарта не восстанавливаются.

Перед вызовом Groq резервируется число токенов по размеру UTF-8 запроса с запасом на ответ. При успешном ответе резерв корректируется по `usage`. При ошибке остаётся консервативная оценка. Дополнительно действует лимит 7000 зарезервированных токенов в календарную минуту. Квоты самого Groq могут считать интервалы иначе: HTTP 429 обрабатывается пропуском, а не задержкой игры.

Перед TTS резервируется число Unicode-символов; при ошибке резерв не возвращается, поскольку запрос мог быть обработан. Счётчики дней и месяцев используют UTC. Они относятся только к этому приложению и этой базе: другие программы с тем же аккаунтом могут расходовать общую бесплатную квоту. Приложение не гарантирует нулевой счёт Google Cloud; лимит нужно согласовать с остальным расходом аккаунта.

Аудио хранится только в памяти процесса, не более 10 МБ, и доступно до истечения срока события. Ссылка содержит случайный короткоживущий ключ доступа и отправляется только аутентифицированным подписчикам соответствующей раздачи. В ссылке нет токена игрока; ответ помечен `private, no-store`. Файлы аудио в репозиторий и SQLite не записываются.

Первый выпуск рассчитан на существующий один серверный процесс. Для нескольких экземпляров потребуется общая доставка событий и аудио, а также распределённое ограничение параллелизма. Запись уникального события и счётчиков в SQLite атомарная, но общий broadcast между процессами не реализован.

В журнал выводятся только краткие статусы, ID события, номер раздачи, язык, режим подписки, расход, наличие аудио и длительность опубликованной реплики. Для ошибок провайдеров выводятся только разрешённые коды причин и HTTP-статус. Ключи, имена, карты, тексты запросов, реплики и исходные сообщения ошибок в журнал не выводятся.

## Если комментатор молчит

В Render → Logs отфильтровать строки по `Commentary`. Дополнительный флаг диагностики не нужен.

- `Commentary configured` — доступность текста и голоса при запуске; это проверка конфигурации, а не доступности API.
- `Commentary subscription` — сервер принял язык и режим клиента. Запись появляется при первой подписке и изменении настроек, без повторов при каждом обновлении стола.
- `Commentary generation started` — начинается запрос к Groq; `Commentary speech started` — озвучка. `Commentary published` означает отправку подписчикам, но не подтверждает воспроизведение браузером.
- `Commentary skipped` с `reason` объясняет пропуск: `no_eligible_facts` — нет подходящего результата, `replay` / `early_finish` — повтор / досрочное завершение, `no_listeners` — нет включённых подписок, `duplicate_or_cooldown` — событие уже зарегистрировано либо ещё действует интервал, `busy` — занят стол или достигнут предел параллельных генераций.
- `hourly_limit`, `minute_token_limit`, `daily_token_limit` — лимиты приложения. `monthly_character_limit` оставляет только субтитры. `text_provider_backoff` / `speech_provider_backoff` — пауза после повторных ошибок.
- `model_silent` — модель выбрала молчание. `invalid_schema`, `invalid_fact_ids`, `empty_text`, `text_too_long`, `markup_or_newline`, `unknown_player_marker`, `numbers_or_brackets`, `wrong_language`, `forbidden_claim`, `repeated_text`, `rendered_text_too_long` — ответ отклонён проверкой текста.
- `expired*` — истёк срок события; `listeners_left*` — подписчики ушли, сменили язык/режим или перешли к следующей раздаче. `Commentary subtitles only` и `Commentary audio discarded` объясняют отсутствие звука.
- `Commentary generation unavailable` / `Commentary speech unavailable` с `reason: provider_http` показывают провайдера и HTTP-статус; `timeout` — превышен срок ожидания, `incomplete_response` — Groq не завершил ответ, `invalid_json` — некорректный JSON. Неизвестные ошибки обозначаются общим кодом без исходного текста.

В SQLite `commentary_events` фиксирует попытку **до** проверки бюджетов и запроса к Groq. Поэтому наличие события при отсутствии строки в `commentary_lines` не доказывает, что запрос был выполнен; причину нужно смотреть в журнале. Сопоставлять записи одной раздачи можно по `eventId`.

## Проверка и запуск

```powershell
npm.cmd --prefix server install
npm.cmd --prefix server test -- --runInBand commentary
npm.cmd --prefix demo run test:client -- --runInBand commentary
npm.cmd --prefix server run build
npm.cmd --prefix demo/client run typecheck
npm.cmd --prefix demo/client run build
npm.cmd --prefix demo run e2e -- commentary.spec.ts voice-chat.spec.ts reconnect.spec.ts
npm.cmd --prefix demo run e2e:mobile -- commentary.spec.ts voice-chat.spec.ts
```

Тест `commentaryFlow.spec.ts` запускает отдельный реальный сервер с временной базой в памяти и заменяет только внешние провайдеры. Проверяет авторизованные WebSocket-подписки, доставку общего аудио для результата и повторного повышения, последующий результат после выдержанной паузы, недействительную ссылку и отсутствие повторной генерации. Браузерные тесты проверяют ожидание нужной версии игры и отмену озвучки торговли при смене улицы. Автоматические проверки не расходуют API-квоты и не подтверждают качество реального голоса.

Перед публичным включением: проверить доступ к выбранной модели и Google Cloud API, прослушать русский и английский голос, измерить задержки и провести игровые сессии. Полный оценочный набор из первоначального плана остаётся следующим этапом.
