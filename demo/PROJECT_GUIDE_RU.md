# Путеводитель по проекту

Этот документ объясняет текущее устройство Omaha Hi-Lo Replay. Инструкции по установке и запуску находятся в [README.md](README.md), правила и технические контракты — в [../TECH_REQUIREMENTS.md](../TECH_REQUIREMENTS.md).

## Структура

```text
Oma/
  .github/workflows/ci.yml     Основной GitHub Actions workflow
  data/                        Локальные SQLite-файлы, не входят в Git
  server/                      Сервер, игровая логика, SQLite и unit-тесты
  demo/
    client/                    React/Vite-клиент и admin.html
    playwright/                Основные и длительные E2E-тесты
    bots/                      Пример внешнего WebSocket-клиента
    package.json               Общие команды разработки и CI
  DEPLOY_RU.md                 Деплой на Render
  TECH_REQUIREMENTS.md         Техническая спецификация
  render.yaml                  Render Blueprint
```

## Архитектура

```text
React-клиент или admin.html
          |
          | HTTP + WebSocket
          v
Express + ws
          |
          +-- игровая логика и встроенный бот
          |
          v
SQLite: сохранённые раздачи
```

Сервер является источником истины. Клиент не рассчитывает победителей и не меняет состояние игры локально: он отправляет действие и получает новую ревизию руки.

В development Vite и сервер запускаются отдельно:

- клиент: `http://localhost:5173`;
- API/WebSocket: `http://localhost:4000`.

В production Express раздаёт файлы из `demo/client/dist`, поэтому нужен только один публичный Node.js-сервис.

## Сервер

Главные файлы:

- `server/src/game.ts` — колода, детерминированная раздача, блайнды, ходы, переходы улиц, выплаты и Omaha Hi-Lo;
- `server/src/bot.ts` — эвристика встроенного бота и выбор pot-limit действий;
- `server/src/handStore.ts` — SQLite-хранилище рук и публичные коды `PA…`/`HA…`;
- `server/src/index.ts` — Express, WebSocket-протокол, приватные состояния игроков, продолжения партий и запуск ботов;
- `server/tests/game.spec.ts` — unit-тесты правил и бота;
- `server/scripts/write-build-info.cjs` — запись commit/build time для `/api/version`.

По умолчанию SQLite создаётся в `data/hands.sqlite` относительно рабочей папки процесса. Для тестов и отдельных окружений путь задаётся через `DATA_FILE`.

### HTTP API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/version` | Commit и время сборки |
| `GET /api/player/:handId/:playerId/:token` | Приватное состояние одного игрока |
| `GET /admin/hands?limit=20&offset=0` | Страница истории |
| `GET /admin/hands/:id` | Полная сохранённая рука для admin/debug |

`limit` ограничивается диапазоном 1–100. Игровое состояние изменяется через WebSocket, а не через HTTP.

### WebSocket-протокол

Основные сообщения клиента:

- `deal` — новая партия из лобби/admin;
- `join_player` — подключение по приватному токену;
- `player_move` — `check`, `bet`, `call`, `raise` или `fold`;
- `new_deal` — следующая рука той же партии;
- `replay_deal` — повтор сохранённого расклада;
- `list` — краткий список рук;
- `replay` — полная рука для debug-клиента.

Основные ответы:

- `hand_dealt`;
- `player_state`;
- `hand_updated`;
- `hands_list`;
- `hand_full`;
- `error`.

Это внутренний протокол прототипа: формальной схемы и версионирования сообщений пока нет.

## Клиент

Главные файлы:

- `demo/client/index.html` — HTML-точка входа React;
- `demo/client/src/main.tsx` — монтирование приложения;
- `demo/client/src/pages/App.tsx` — лобби, приватный стол, debug-страница, статистика и стили;
- `demo/client/admin.html` — автономная admin-страница;
- `demo/client/vite.config.ts` — сборка `index.html` и `admin.html`;
- `demo/client/public/cards/revk` — основные SVG-карты;
- `demo/client/public/cards/court` — исходники иллюстраций валетов, дам и королей.

Маршруты React:

- `/` — лобби, создание партии и replay по коду;
- `/player/:handId/:playerId/:token` — приватный игровой стол;
- `/debug/:handId` — технический просмотр сохранённой руки.

`/admin.html` не является React-маршрутом: это отдельная страница, которая напрямую использует HTTP API и WebSocket.

### Что показывает игровой стол

- закрытые карты соперников и четыре карты текущего игрока;
- пять позиций борда и текущую улицу;
- банк, блайнды, стеки и последнее действие каждого места;
- текущие High/Low-комбинации игрока;
- доступные действия и размеры `Blind`, `1/4 pot`, `1/2 pot`, `Pot`;
- итог High/Low, все руки и накопительную статистику после showdown;
- переход к следующей руке и replay сохранённого расклада.

На showdown карты раскрываются автоматически. Отдельного голосования `Show cards` в текущей версии нет.

## Модель данных

`DealtHand` содержит:

- внутренние UUID руки и партии;
- короткие `handCode` и `partyCode`;
- `handNumber`, `dealSeed` и переносимый `dealCode`;
- игроков, токены, карты, признаки ботов и стеки;
- полный борд и открытую часть борда;
- улицу, текущего игрока, ставки раунда и счётчик повышений;
- блайнды, банк, журнал действий и ссылки на продолжение/replay.

Сейчас вся рука хранится одной JSON-строкой в таблице SQLite `hands`. Миграций и нормализованной схемы таблиц нет.

## Боты

Встроенный бот работает внутри серверного процесса:

- оценивает стартовую руку и текущие High/Low-комбинации;
- учитывает цену колла, банк и лимит повышений;
- выбирает Fold, Check, Call, Bet или Raise;
- продолжает ход после задержки `BOT_THINK_MS`.

`demo/bots/exampleBot.ts` — отдельный минимальный WebSocket-клиент для экспериментов. Он не участвует в обычной игре и запрашивает полную руку через debug-сообщение `replay`.

## Тесты

Unit-тесты в `server/tests/game.spec.ts` проверяют:

- детерминированность и отсутствие повторяющихся карт;
- блайнды, очередность, перенос стеков и all-in;
- Check/Bet/Call/Raise/Fold и pot-limit суммы;
- лимит трёх повышений;
- переходы улиц и автоматическое раскрытие;
- High/Low, отсутствие qualifying low и комбинации;
- продолжение партии, replay и поведение бота;
- стол до 10 игроков.

Основные Playwright-тесты проверяют стабильную раскладку мест, ход бота, доступность кнопок, статистику и продолжение партии. Длительный сценарий запускает семь ботов и семь наблюдающих клиентов на 20 рук.

Команды из `demo`:

```powershell
npm.cmd test
npm.cmd run e2e
npm.cmd run e2e:bots
npm.cmd run ci
```

E2E использует отдельные файлы `data/e2e-hands.sqlite` и `data/e2e-bots.sqlite`.

## Как проходит одна команда игрока

1. Приватная страница отправляет `player_move` с UUID руки, id игрока, токеном, действием и при необходимости суммой.
2. Сервер проверяет токен, очередь, стек, текущую ставку и лимит повышений.
3. `recordPlayerMove` меняет банк, стек, журнал и текущего игрока либо открывает следующую улицу.
4. Рука сохраняется в SQLite.
5. Отправителю возвращается `player_state`, остальным соединениям — публичный `hand_updated`.
6. Если очередь перешла к боту, сервер планирует его ход.

## Известные технические ограничения

- side pots не реализованы;
- нет регистрации, ролей и серверной авторизации admin/debug;
- приватность игрока основана на секретном URL-токене;
- WebSocket-протокол не имеет формальной схемы и версий;
- серверные таймеры ботов живут в памяти и восстанавливаются только при новом подключении игрока;
- SQLite подходит для одного процесса, но не для горизонтального масштабирования;
- основная страница и стили собраны в одном большом `App.tsx`;
- отдельный `demo/github/workflows/ci.yml` — устаревшая копия и не используется GitHub, потому что не находится в корневой `.github/workflows`.

## Термины

- **Node.js** запускает сервер и инструменты сборки.
- **npm** устанавливает зависимости и запускает scripts из `package.json`.
- **TypeScript** добавляет типы к JavaScript.
- **React** строит интерактивный интерфейс.
- **Vite** запускает dev server и собирает frontend.
- **Express** обслуживает HTTP API и production-статику.
- **WebSocket** доставляет обновления стола в реальном времени.
- **SQLite** хранит историю в одном локальном файле.
